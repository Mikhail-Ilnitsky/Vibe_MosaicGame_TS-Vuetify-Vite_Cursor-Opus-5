# Игра-мозаика

Адаптивная браузерная игра-мозаика: картинка делится на квадратные фрагменты, которые нужно вернуть
на свои места. Это чистый фронтенд (SPA) без бэкенда и базы данных — вся логика работает в браузере.

**Демо:** https://mikhail-ilnitsky.github.io/Vibe_MosaicGame_TS-Vuetify-Vite_Cursor-Opus-5/

## Возможности

- **Галерея с локализацией.** Шесть картинок разных пропорций; название показывается на выбранном
  языке — при наведении на десктопе и подписью под миниатюрой на смартфоне. Язык (RU/EN)
  определяется по `navigator.language` и переключается в правом верхнем углу.
- **Расчёт сеток сложности.** По меньшей стороне картинка делится на 5…11 частей, по большей число
  фрагментов подбирается так, чтобы они оставались строго квадратными; остаток исходника
  обрезается, а сетка центрируется на картинке.
- **Управление двумя способами одновременно.** Клик-клик (первый фрагмент выделяется рамкой, второй
  меняется с ним местами) и перетаскивание на Pointer Events — одинаково работает мышью и пальцем.
  Порог drag — половина фрагмента: меньше считается кликом.
- **Адаптивное поле.** Мозаика всегда вписывается в свободную область экрана без прокрутки и не
  растягивается выше масштаба 1:1.
- **Счётчик ходов.** Ход — это обмен двух фрагментов; счётчик виден в процессе игры и в финале.
- **Просмотр оригинала.** Кнопка показывает исходную картинку в том же размере и с тем же
  обрезанием краёв, что и собираемый пазл.
- **Анимация победы.** Собранная сетка мигает жёлтым 500 мс, затем исчезает, оставляя обрезанную
  картинку, а под ней плавно появляются сообщение «У вас получилось!» и кнопка новой игры.

## Происхождение проекта

Исходная версия сгенерирована в Cursor по техническому заданию [`prompts/INITIAL.md`](prompts/INITIAL.md).
Подробный контекст проекта для следующих сессий — [`.cursor/CONTEXT.md`](.cursor/CONTEXT.md).

## Запуск

```bash
npm install      # установка зависимостей
npm run dev      # разработка: http://localhost:5173
npm run build    # проверка типов + production-сборка в dist/
npm run preview  # предпросмотр собранного проекта
npm run type-check  # только проверка типов (vue-tsc)
```

Деплой выполняет workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) при пуше в
`main`. В репозитории нужно один раз выбрать **Settings → Pages → Build and deployment → Source:
GitHub Actions**. В разработке приложение работает из корня сайта, а production-сборка использует
базовый путь `/<имя-репозитория>/` (в CI он передаётся переменной `BASE_PATH`).

## Структура

```
src/
├── App.vue                      # переключение экранов: галерея → сложность → игра, шапка
├── main.ts                      # точка входа: подключение Vuetify и глобальных стилей
├── types.ts                     # общие типы: картинка, сетка, фрагмент, экран
├── components/
│   ├── LanguageSwitcher.vue     # переключатель RU/EN в правом верхнем углу
│   ├── GalleryScreen.vue        # галерея миниатюр с локализованными названиями
│   ├── DifficultyScreen.vue     # выбор сетки разбиения и превью картинки
│   ├── GameScreen.vue           # счётчик ходов, просмотр оригинала, выход, экран победы
│   └── PuzzleBoard.vue          # мозаика: фрагменты, клик-клик, drag на Pointer Events
├── composables/
│   ├── usePuzzle.ts             # состояние партии: порядок фрагментов, обмены, ходы, победа
│   ├── useBoardSize.ts          # подгонка поля под свободную область экрана
│   └── useImageMeta.ts          # загрузка натуральных размеров картинки перед нарезкой
├── data/
│   └── images.ts                # список картинок с прямыми ссылками и названиями RU/EN
├── i18n/
│   ├── index.ts                 # определение языка, реактивная локаль, функция t()
│   └── messages.ts              # словари RU/EN и типы ключей
├── plugins/
│   └── vuetify.ts               # тема и явный импорт используемых компонентов Vuetify
├── styles/
│   └── main.css                 # глобальные стили: белый фон, нескроллящаяся раскладка
└── utils/
    └── grid.ts                  # математика сеток, проценты background-position, перемешивание
```
